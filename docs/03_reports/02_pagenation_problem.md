# 임베드와 플레이리스트 간의 페이지네이션

## 📌 문제 발생

1. 문제 유형 (핵심 태그) 정의

- 퍼포먼스
- 정책 관리
1. 어떤 기능에서 문제가 발생했는가?
    - 플레이리스트는 소유한 데이터베이스에서 데이터를 끌어오지만 임베드는 유튜브 서버에서 가져옴

---

## 🔍 원인 분석

- 왜 발생했는가?
    - 플레이리스트는 데이터베이스를 조작해서 가져오나, 임베드 API는 유튜브 서버쪽에서 가져온다. 플레이리스트는 현재 서버에서 추가적으로 데이터를 가져와서 조립하면 되나, 임베드는 가상 플레이리스트를 사용해서 데이터를 끌어오는 역할을 합니다. 이 지점에서 문제가 발생했습니다.
- 어떤 코드/구조에서 문제가 있었는가?
    - 플레이리스트는 페이지네이션을 하면서 자연스럽게 다음 스크롤이 로딩되나, 임베드 영역에선 1/10 (데이터 가져옴)→ 1/20이 되는게 아니었습니다. 가상으로 된 플레이리스트에선 실시간으로 데이터를 넣어줄 수 없었습니다.

---

## 🛠 해결 방법

- 어떻게 해결했는가?
    - 미리 데이터를 불러왔다가, 10곡이 끝났을 때 다음 10곡을 적용하게 됩니다. 즉 가상 플레이리스트를 비우고 다음 10곡을 채우는 형식으로 진행됩니다. 10곡이 끝나기 전에 새로운 임시 플레이리스트를 지정하면 현재 재생하던 부분이 날아가서 이런 조치를 취하게 되었습니다.
